# Construct 0.8.3

A point release behind 0.8.2: sign-up codes now actually send, and the last
screen of the intake says what went wrong when it cannot write your projects.

## Sign-up codes send

0.8.2 shipped the code screens and the backend that answers them, and the two
were never introduced to each other in production — the deployed service
predated the commit that sends real mail, so the window asked for six digits
and the endpoint that would have emailed them did not exist yet.

The service now runs that code, with a sending key and a verified from-address
behind it. Creating an account, signing in with a code and resetting a
forgotten password all send a real email. Nothing in the window changed; it was
right all along.

## The openings screen

If Construct cannot write your three projects, the screen used to say "I could
not reach a model to write these" — which was the one explanation it could be
certain was wrong. With no model reachable, Construct composes a project out of
your own answers instead, so that screen never runs out of things to suggest.
An empty one means the request never arrived, and the reason was being caught
and thrown away.

So the reason is kept and shown, quietly, in the failure's own words. The card
says what is true: something went wrong, everything you told me is saved, and
you can still start a project by hand. **Had something else in mind?** no
longer sits underneath it, since it leads into the same call that just failed.

Under the cards, one line instead of three. The keyboard hint and the way to
ask for something else share a row, and the step's status line goes quiet once
the cards can speak for themselves. A slot is also the height of the card that
replaces it, so the second and third no longer shift as they land.

## The empty screens

The project list, the atlas and the atlas's entry pane said nothing when they
had nothing — a dashed rectangle around a framed icon, which is a placeholder
drawn as an object.

They are centred columns on the window's own surface now: an unframed mark, a
real heading, one line saying what has to happen, and the action that makes it
happen. The project list says what a project in Construct actually is — a
folder on your disk, with your files and your git history — and offers to start
an empty one or bring in something you are already working on. The atlas says
that it draws itself out of what you are taught, and offers the way to a
project, since there is nothing to chart until one exists.

Page titles are also the size they were drawn to be. `text-title` had no size
token behind it, so Tailwind generated no such class and three headings had
been body text in bold since 0.7.

## Installing

- **macOS** — `Construct-0.8.3-arm64.dmg` for Apple Silicon,
  `Construct-0.8.3.dmg` for Intel.
- **Windows** — `Construct-0.8.3-x64.exe`.
- **Linux** — `Construct-0.8.3-x86_64.AppImage` or `Construct-0.8.3-amd64.deb`.

If you are on 0.8.0, 0.8.1 or 0.8.2, Construct will offer this to you itself.

These builds are not code-signed. macOS will ask you to approve Construct the
first time (Right click → Open, or System Settings → Privacy & Security →
Open Anyway), and Windows SmartScreen will ask for the same.

## Deploying the backend

No database migration, and no new variables beyond the `RESEND_API_KEY` and
`EMAIL_FROM` that 0.8.2 already documented. The one thing worth checking is
that the deployment is running the commit that sends mail: the service starts
happily without those routes, and a window asking for a code cannot tell the
difference until someone tries to sign up.
