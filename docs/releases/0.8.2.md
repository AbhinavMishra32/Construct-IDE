# Construct 0.8.2

Accounts finish signing up, the intake ends with three projects worth
building, and the agent can actually read the web instead of only searching
it. Plus a change log for every concept, and a Windows sidebar that is
translucent rather than grey.

## Signing up works

Construct's window has asked for a six-digit code since 0.8.0, and nothing
could send one — the backend ran email and password only, so the code screens
answered "Emailed sign-in codes are not switched on for this account yet."

They are now switched on, and all three flows are live:

- **Creating an account** sends a code to your address and signs you in when
  you type it.
- **Signing in with a code** works without a password at all.
- **Forgot your password** sends a code, takes a new password, and signs you
  straight in — resetting revokes every other session, so a device you no
  longer trust loses its access in the same step.

Codes rather than links, deliberately: the thing that asked for one is a
desktop window that is still open and waiting for six digits, and a link would
have to bounce through a browser and back to return you to a window that never
closed. A code lasts ten minutes, works once, is stored hashed, and burns after
five wrong guesses. If you had signed up on 0.8.0 or 0.8.1 and could never
confirm your address, signing in now sends the code and picks up where the
sign-up stopped.

Sessions last a month, refreshed as you use the app, so the window stops
signing itself out.

## Your first project

The intake used to end with a portrait and a button to an empty project list,
which is the one moment Construct knows most about you and the moment it asked
you to think of something to build.

It now ends with **three projects written for you** from the same answers the
portrait came from: a name, what you will be able to do at the end of it, one
line on why this one for you, and what you will have built. Starting one
creates the project and drops you into it already running — Construct researches
the goal and takes the first teaching turn as it opens, and it greets you there.
Press 1, 2 or 3 to start one from the keyboard, or describe your own as before.

## The web

- **Construct reads pages now.** It has been searching and writing from the
  short extracts a search returns, because its instructions named a fetch tool
  it does not have. It now opens the best one or two results in full before it
  teaches from them.
- **Searches that found things say so.** Results were being discussed in the
  agent's own prose while the row above them read "Nothing came back for this
  one" — long tool output was cut off mid-JSON, which left the results
  unreadable to the app that had just fetched them.
- **A search looks like a search.** The query, how many results, and then each
  result with its real favicon, title, site, date and extract. Clicking one
  opens it in your browser. Pages the agent read in full are listed the same
  way, instead of as a wall of raw payload.
- **Links are links.** `[a page](https://…)` used to reach you exactly like
  that, brackets and all. Both written links and bare URLs now render, and open
  externally.

## Concepts

Construct has recorded every reading it has ever taken of every idea — first
taught, moved up, moved down, returned to — since the very first version, and
until now nothing showed it to you.

- **Each concept has a history**, newest first, on a rail: where the level
  moved, why, and which parts of the note were rewritten.
- **The transcript's concept cards say what changed.** They used to show a level
  and nothing else, so a turn that came back to an idea and rewrote its note
  read as though nothing had happened.

## Memory

Memory rows used to say "Remembered learner.md", which told you a filename,
called an update a memory, and did it every single turn. They now say what
actually moved — recalling what it knows about you, updating what it knows about
this project — and recalling and updating no longer share a word or an icon.

Questions also stop being timed. "Asked a question in 25s" was a stopwatch held
on you while you thought.

## Windows

**The sidebar is translucent.** It is a hole punched in the window for the
system's own material to show through, and on Windows that material was Mica —
a wallpaper sample held still, which reads as a flat grey panel. Windows 11 22H2
and later now get Acrylic, which genuinely blurs what is behind the window, and
the tint over it was re-balanced for it. Earlier Windows 11 builds keep Mica;
Windows 10 keeps its opaque sidebar, which is what it has always had. macOS is
untouched, and tests now hold it that way.

## Installing

- **macOS** — `Construct-0.8.2-arm64.dmg` for Apple Silicon,
  `Construct-0.8.2.dmg` for Intel.
- **Windows** — `Construct-0.8.2-x64.exe`.
- **Linux** — `Construct-0.8.2-x86_64.AppImage` or `Construct-0.8.2-amd64.deb`.

If you are on 0.8.0 or 0.8.1, Construct will offer this to you itself.

These builds are not code-signed. macOS will ask you to approve Construct the
first time (Right click → Open, or System Settings → Privacy & Security →
Open Anyway), and Windows SmartScreen will ask for the same.

## Deploying the backend

The cloud service refuses to start in production without `RESEND_API_KEY` and
`EMAIL_FROM`, on purpose: a deployment that cannot send email cannot finish a
sign-up it has already accepted. `EMAIL_FROM` has to be an address on a domain
verified with Resend. Running the backend from source needs neither — the code
is written to the service log instead of being emailed.

No database migration. The `verification` table the codes live in has existed
since `001_initial.sql`.

## Known gaps

- Linux and Windows builds are x64 only; there are no arm64 packages for either.
- Changing the email address on an existing account is not in the window yet,
  though the backend can send the code for it.
