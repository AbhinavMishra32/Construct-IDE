# Construct 0.8.1

A fix release for Windows. 0.8.0 was laid out as though every machine had macOS
traffic lights, and on Windows that put the chrome in two wrong places at once.
Everything below is the same application — only the window's first row moved.

## Windows

- **The home and navigation buttons sit in the top-left corner again.** Construct
  reserves room on the leading edge of its first row for the macOS traffic
  lights. On Windows there are no traffic lights there, so the reservation was
  pure empty space and the buttons it pushed aside — All projects, back, forward
  — started an inch and a half into the window. They now start at the corner.
- **Construct's own toolbar buttons no longer sit under minimise/maximise/close.**
  Windows draws its caption buttons over the trailing edge of our first row, and
  0.8.0 reserved nothing for them: the toolbar's actions were underneath, which
  meant clicking one could close the window. The trailing reservation now comes
  from the caption overlay itself — Windows publishes the strip it leaves us —
  so it follows the display scale and the zoom level instead of trusting a width
  measured once at 100%.
- **Linux** had the same stray leading inset, for the same reason, and loses it
  too. A native frame keeps its buttons outside our content, so nothing is
  reserved on either edge.

The cause was one rule in the wrong place: the platform overrides were written
inside a CSS `@layer` while the defaults they were meant to override were not,
and an unlayered declaration beats a layered one however specific the layered
selector is. So the overrides parsed, validated, and never applied — and on
macOS, where the defaults are already correct, nothing looked wrong. A test now
asserts that those two rules stay outside every layer.

## Also fixed

- **Deleting your account works.** `DELETE /v1/account` is live on the API.
  Settings → Account → Delete account now removes your projects, messages,
  concepts, tasks, path and memory, and then the account itself, in one
  transaction. This was the first item under 0.8.0's known gaps; it needed no
  app update, so 0.8.0 can do it too.

## Installing

- **macOS** — `Construct-0.8.1-arm64.dmg` for Apple Silicon,
  `Construct-0.8.1.dmg` for Intel.
- **Windows** — `Construct-0.8.1-x64.exe`.
- **Linux** — `Construct-0.8.1-x86_64.AppImage` or `Construct-0.8.1-amd64.deb`.

If you are on 0.8.0, Construct will offer this to you itself — this is the first
release to arrive through the updater rather than by download.

These builds are not code-signed. macOS will ask you to approve Construct the
first time (Right click → Open, or System Settings → Privacy & Security →
Open Anyway), and Windows SmartScreen will ask for the same. Signing certificates
are configured through repository secrets, and the moment they exist these same
builds are signed and notarized with no other change.

## Known gaps

- Linux and Windows builds are x64 only; there are no arm64 packages for either.
